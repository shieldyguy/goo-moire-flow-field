# Settings transport: extracting the preset-code system into a library

A plan for turning "share a group of user-editable settings as a short code or
link, and have every old code keep loading" into a reusable, domain-neutral
library.

The working goal, in the user's words: *"as we develop settings that are
important to the thing and user editable, let's keep them all in the preset
block so our encode/decode system stays plumbed."*

## Where the idea has been

This is one idea in its fourth generation, and the generations are not equal.

1. **toon skin, old Jazzman** (`LocalDSP/platforms/wasm/skins/toon/main.js`).
   `#<base64url>`: a version byte, then one 7-bit MIDI CC value per parameter
   named in `share_schemas.json[version]`. Decoded by replaying CCs. Already
   had the one idea that matters: **the schema is a list of parameter names
   per version, kept forever**, generated from the parameter table.

2. **svg skin, today** (`LocalDSP/platforms/wasm/skins/svg/share.js`, plus
   `ensemble.js`, `library.js`, `api/_library.js`). Shared by **Jazzman,
   Bonkman, JM26 and Westkraft**; `jm26-site` is a byte-identical copy made by
   `deploy-jm26.sh`. A code is `<version>.<data>[.<pattern>][~<ensemble>]`:
   - `data`: every `category: "preset"` parameter as a 10-bit position,
     bit-packed in schema order.
   - `share_schemas.json` is generated by `gen_share_schema.py` on every
     `make wasm`, from `ui_params.json`, from the C descriptor table. It bumps
     only when the name list or a parameter's `scale/min/max` changes, and it
     is a tracked **ledger**: versions are only ever appended.
   - An old code sets what it names; the rest keeps its current value; a
     parameter whose scale or range changed is **converted by value**
     (`migratePosition`); a name the engine no longer has is skipped.
   - The pattern part (melody or FRP record, own format byte) and the
     ensemble part (gzip'd float32 blob) decode independently; one this page
     can't read is **skipped with a sentence**, and the sound still loads.
   - The shared library stores **exactly the code string**, validated
     server-side by a regex and a 400-character limit.
   - Westkraft is at **schema version 26**: adds, removes, renames, 13
     rescales, the same `_NOTE` parameters leaving and coming back. Never a
     reorder, because order is enum order. Every one of those codes still
     loads. This is the stress test any replacement has to pass.

3. **goo-moire** (`src/lib/encoding/presetEncoder.ts`), built independently.
   A fixed-offset struct with a version byte and a hand-written decoder
   cascade `v3 → v4 → v5`, no name list. It is the one with drift
   (`goo.driftFriction` is in the UI but not the encoder) and the one that
   duplicates its settings type in three files. Useful as a regression
   fixture and a second consumer; not a design input.

4. **The library.** Generation 2 is the design. The job is to extract it, cut
   it free of audio, and make the schema something a project can hand-write
   as well as generate.

## What is general, and what is not

The library owns, with zero dependencies and no DOM:

- **Schema**: an ordered, named set of fields, each with a codec and a
  default. Built from plain data at runtime (LocalDSP: from `ui_params.json`)
  or written as a TypeScript literal (a React app) with `Infer<typeof schema>`
  as the settings type.
- **History**: the ledger of every published schema version. Its file format
  is a **superset of `share_schemas.json`**, so the four existing ledgers
  load unchanged: `{ "<v>": [names…], "meta": { "<v>": { name: {scale, min,
  max} } } }` is a valid history where every field is a 10-bit `quantized`.
  New ledgers may also record a per-field codec.
- **Codecs**: bit-width primitives through one MSB-first bit writer
  (`pack10` and goo's byte struct are the same machine):
  `bool`, `uint(bits)`, `int(bits)`, `quantized({bits, min, max, curve})`,
  `scaled({bits, scale})`, `enumOf(labels)` (stored by index, **migrated by
  label**), `group`, `local(default)` (in the type, not on the wire),
  `custom`.
- **Migration rule**, lifted from `share.js`: if a field's codec parameters
  are identical between the code's version and the current one, pass the raw
  integer through untouched (bit-exact with today's behavior); otherwise
  decode with the old codec to a value and re-encode with the new one,
  clamped. Enums go index → old label → current index.
- **Grammar**: `<version>.<main>[.<section>…]`, today's grammar, kept as the
  canonical one because four projects and a stored library already speak it.
  Sections after the first carry a format byte and decode independently.
  `~` stays accepted as a separator. `isCode(text, {maxLength})` for servers.
- **Report**: `{ version, set, defaulted, dropped, converted, skipped:
  [{section, reason}] }`, so a page can say "41 settings set, 2 converted
  from an older version; the melody part was skipped: this page has the FRP
  panel".

What stays outside core, as registrations and adapters:

- **Curves.** `octaves`, `rc_octaves`, `bipolar_expo` and friends mirror
  `lib/framework/param_system.c`. Core ships `linear` and a `registerCurve`
  hook; LocalDSP registers its set in one file.
- **The parameter bus.** `bridge.has/get/set/on` works in 0..1 positions. An
  adapter maps decoded fields onto it; the library never knows what a bridge
  is.
- **Pattern records and the ensemble.** Melody and FRP become declared
  section schemas with their own history (which fixes the latent "insert a
  select option, break old codes" bug by migrating enums by label). The
  ensemble stays an `opaque` section: the engine remaps its own schema.
- **Transport.** Fragment (`#code`) for LocalDSP, query (`?p=`) for goo
  because its OG image route reads it server-side. `cleanInput` accepts a
  pasted link, a `#code`, or a bare code.
- **DOM.** Buttons, status lines, the paste box stay in each page. A
  framework-free controller carries the behaviors `setupShare` implements
  (debounced current code, copy code / copy link, apply, summary words) with
  callbacks instead of selectors, and returns the same `{code, apply,
  summary}` that `library.js` consumes today.

## Constraints learned from LocalDSP

- "No hardcoding, this is a platform": behavior is driven by the descriptor
  table. The library must therefore accept a schema as **data**, and the
  TypeScript literal form is sugar on top, not the primary API.
- Consumption is plain ESM copied by `make wasm` into `dist/wasm/<project>/`
  and served as files (Westkraft from LocalDSP's own Vercel build, JM26 via
  rsync into `jm26-site`). The library ships as **one dependency-free ESM
  file plus `.d.ts`**, vendored into `platforms/wasm/skins/svg/`. The same
  artifact installs from npm for bundler projects. This is about reach, not
  about WASM or audio.
- `api/_library.js` duplicates the code regex. It should import `isCode`.
- The generator already enforces the workflow for LocalDSP (schema from
  descriptors, bump on `make wasm`). The library's job there is to make the
  ledger check a test (`assertHistory`: current schema equals the latest
  version; history is append-only) and to let the generator shrink to "emit
  the current field list". For hand-written schemas the same test plus
  `Infer<>` is the enforcement: a setting not in the schema cannot be in the
  typed settings object, and a schema change without a version bump fails CI.

## Phases

1. **Extract core** into a new repository. Port `share.js`'s format, scales,
   `pack10`, `migratePosition`, grammar and messages, generalized as above.
   Tests are **the four real ledgers**: for every project and every version,
   generate codes at random positions and check that the library decodes them
   to exactly what today's `decodeCode` produces (both run in the same test).
   Plus goo's v3/v4/v5 URLs, plus any codes exported from the Westkraft and
   JM26 shared libraries. Westkraft v1 → v26 is the gate.
2. **Adapters**: `bridge` (positions), `link`, `controller`, `server`
   (`isCode`), `react` (read once on mount, `share()` returns the URL; live
   URL rewriting opt-in, since nothing does it today).
3. **LocalDSP svg skin adopts it.** `share.js` shrinks to DOM wiring, the
   curve registry and the three section declarations; `melody.js`/`frp.js`
   expose schemas instead of byte layouts; `_library.js` imports `isCode`.
   One change reaches Jazzman, Bonkman, JM26 and Westkraft. Gate: every
   version in every ledger decodes identically, `make wasm` for each project,
   and a round trip on each page.
4. **Generality test**: the next non-audio project writes its schema by hand,
   with no legacy to carry. If the API bends toward sliders or positions
   there, the API is wrong, not the project.
5. **goo-moire**: a sealed `legacy.ts` for v0–v5, a hand-written schema v6,
   the three duplicated interfaces replaced by `Infer<>`, `driftFriction`
   added as the first field that cannot drift.
6. **Docs**: README with the contract to paste into a project's `CLAUDE.md`:

   > User-editable settings live in the preset schema. Add a field there
   > first; the type, encoder, decoder and link handling follow. Run the
   > history snapshot before committing. Never edit the history ledger by
   > hand.

## Decisions to make

- Package name and home. Recommendation: its own repo, vendored into
  LocalDSP as one file, published to npm for bundler projects.
- Whether melody/FRP become declared schemas in phase 3 or stay opaque
  sections until later. Recommendation: declared, because the label-migrated
  enum is a real fix.
- Whether the toon skin's generation-1 links need a `legacy` reader, or
  whether no such links are live anymore.
